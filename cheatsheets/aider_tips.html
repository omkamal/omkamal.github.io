Aider Visual Usage Tips & Pair-Programming Workflows

1. Curate Minimal Chat Context

Only add files that actually need edits or direct signatures. Stuffing unrelated modules into chat dilutes attention and increases token cost.

  • /add <file> — Add only files being actively edited
  • /read-only <file> — Expose reference types/interfaces safely
  • /tokens — Audit exact context window usage per file

2. Decompose Goals into Atomic Steps

Ship one vertical slice at a time so every Git auto-commit stays reviewable, testable, and trivial to /undo.

  • /drop completed files before starting the next subsystem
  • /diff — Inspect the exact Git diff Aider just committed
  • /undo — Instantly revert the last AI commit if needed

3. Plan Complex Refactors First

Separate architectural design from code edits so you agree on data flow before touching source files.

  • /ask <question> — Discuss architecture & edge cases without editing any files
  • /architect — Use a frontier reasoning model to plan and a fast coder model to apply diffs
  • /code <instruction> — Execute the agreed plan right after /ask

4. Unsticking Loops & Hallucinations

When an edit misses the mark twice, avoid arguing in a polluted thread — reset context cleanly:

  • /clear — Wipe stale conversation history while keeping added files
  • /drop <file> — Prune noisy or distracting files from context
  • /model <name> — Switch to a stronger reasoning model mid-session
  • Manual + AI turns — Sketch the function signature yourself, let Aider fill in implementation

5. Close the Loop with /run & /test

Feed real stack traces and compiler diagnostics straight back into Aider instead of summarizing errors manually.

  • /test <cmd> — Run test suite and share output automatically on failure
  • /run <cmd> — Execute any shell command and optionally share stdout/stderr
  • --auto-test — Run your test command automatically after every AI edit

6. Ground Unfamiliar APIs with Docs

Prevent deprecated SDK hallucinations on newly released libraries by injecting authoritative docs:

  • /web <url> — Scrape and include live documentation pages directly in chat
  • /read-only CONVENTIONS.md — Enforce project coding rules across every prompt
  • Paste minimal working examples from official release notes

7. Fast Multi-Line Input & Interrupt Controls

  • Ctrl+C — Safely interrupt a streaming response mid-generation without losing your session
  • { ... } — Wrap prompts in curly braces on their own lines for clean multi-line instructions
  • /paste — Paste multi-line code or clipboard images (UI screenshots / mockups) directly into chat
  • /editor — Open your system $EDITOR (Vim / VS Code / Nano) to compose complex specifications
